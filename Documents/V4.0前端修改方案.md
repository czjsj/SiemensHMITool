# Claude Code 前端实施任务书

# Siemens HMI Assistant 前端 V4 自动 HMI 生成与部署工作台

## 一、总体目标

将现有前端从“自然语言生成 IR / XML”的工具页面，升级为完整的“自动 HMI 生成与部署工作台”。

最终前端流程必须支持：

自然语言输入  
→ SSE 流式 AI 生成  
→ IR / HmiProjectSpec 预览  
→ 变量表预览  
→ 控件绑定预览  
→ 模板原型匹配结果  
→ 能力校验  
→ 部署计划预览  
→ Dry-Run  
→ 真实部署  
→ 编译  
→ 验证  
→ 诊断报告展示。

# 阶段 0：前端现状审计与保护

## 目标

在修改前端前，先确认当前项目结构、框架版本、状态管理方式、API 封装方式和主页面入口，避免破坏旧功能。

## 需要检查

请先检查以下目录或文件是否存在：

```text

frontend/src/views/
frontend/src/components/

frontend/vite.config.*
```

如果项目没有 `frontend/` 目录，请先定位 Vue SPA 实际目录。

## 执行步骤

1. 检查前端框架版本：
   
   - Vue 2 还是 Vue 3
   
   - 是否使用 Vite
   
   - 是否使用 TypeScript
   
   - 是否使用 Pinia / Vuex
   
   - 是否使用 Element Plus / Naive UI / Ant Design Vue / 自定义组件

2. 检查现有 API 调用封装：
   
   - 是否已有 `api.ts`
   
   - 是否已有 `request.ts`
   
   - 是否已有 axios/fetch 封装
   
   - 是否已有 SSE 处理函数

3. 检查当前页面：
   
   - 自然语言输入在哪里
   
   - `/api/generate` 在哪里调用
   
   - 预览图在哪里显示
   
   - XML 构建或导入按钮在哪里
   
   - TIA 连接状态在哪里显示

4. 新增文档：

```text

```

记录当前发现的前端结构。

## 验收标准

- 不删除旧页面。

- 不删除旧 API。

- 能正常启动当前前端。

- 新增 `frontend/docs/frontend_v4_migration_notes.md`。

- 明确当前使用的是 Vue 2/Vue 3、Pinia/Vuex/无状态管理、axios/fetch。

```ts
export async function getJson<T>(url: string): Promise<T> {
  const res = await fetch(url)
  if (!res.ok) throw new Error(await res.text())
  return res.json()
}

export async function postJson<T>(url: string, payload?: any): Promise<T> {
  const res = await fetch(url, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(payload ?? {}),
  })
  if (!res.ok) throw new Error(await res.text())
  return res.json()
}
```

## 2.3 `api/generation.ts`

封装旧 SSE 接口：

```ts
export interface GenerateOptions {
  prompt: string
  withReview?: boolean
  target?: any
  template_xml?: string
  config?: Record<string, any>
}

export function streamGenerate(
  options: GenerateOptions,
  onEvent: (eventName: string, data: any) => void,
  onError?: (error: any) => void,
  onDone?: () => void,
) {
  const endpoint = options.withReview
    ? '/api/generate/with_review'
    : '/api/generate'

  return streamPostSse(endpoint, options, onEvent, onError, onDone)
}
```

如果项目已有 SSE 处理函数，请复用现有代码。否则实现 `streamPostSse`，必须支持：


## 主流程实现

### 8.1 生成 IR

点击“生成 IR”：

1. 清空旧 diagnostics。

2. 调用 `/api/generate` 或 `/api/generate/with_review`。

3. 追加 SSE 日志。

4. 如果事件中有 IR，保存到 generationStore。

5. 提取 tags 到 VariableTable。

6. 提取 screen items 到 BindingTable。

7. 显示预览图，如有。

### 8.2 校验

点击“校验”：

1. 调用 `/api/hmi/validate`。

2. payload 包含：
   
   - ir 或 spec
   
   - target

3. 展示返回 diagnostics。

4. 成功后状态变为 `VALIDATED`。

5. 有 error 时状态变为 `BLOCKED`。

### 8.3 生成部署计划

点击“生成部署计划”：

1. 调用 `/api/hmi/plan`。

2. payload 包含：
   
   - ir 或 spec
   
   - target
   
   - dry_run: true

3. 保存 plan。

4. 显示 DeploymentPlanTimeline。

5. 如果 plan 有 error，状态为 `BLOCKED`。

### 8.4 Dry-Run

点击“Dry-Run”：

1. 调用 `/api/hmi/deploy`。

2. payload：
   
   - dry_run: true
   
   - ir 或 spec
   
   - target
   
   - template_xml

3. 返回 mode=DRY_RUN 时显示：
   
   - “预演通过，未导入 TIA”

4. 不允许显示“部署成功”。

### 8.5 真实部署

点击“真实部署”：

1. 先检查 opennessStore.connected。

2. 如果未连接，提示连接 TIA。

3. 调用 `/api/hmi/deploy`。

4. payload：
   
   - dry_run: false
   
   - ir 或 spec
   
   - target
   
   - template_xml

5. 处理结果：
   
   - status=NOT_CONNECTED：显示未连接，不显示成功。
   
   - status=BLOCKED：显示阻断原因。
   
   - status=DEPLOYED：显示部署成功。
   
   - status=FAILED：显示失败和 diagnostics。

### 8.6 编译

点击“编译”：

1. 调用 `/api/hmi/compile`。

2. 显示 CompileResultPanel。

3. 成功后状态 `COMPILED`。

4. 失败后状态 `FAILED`。

### 8.7 验证

点击“验证”：

1. 调用 `/api/hmi/verify`。

2. 显示 VerificationResultPanel。

3. 无 TIA 连接时不能显示验证成功。

4. 成功后状态 `VERIFIED`。

## 验收标准

- 主页面能完整走通：生成 → 校验 → 计划 → Dry-Run。

- 未连接 TIA 时真实部署显示 NOT_CONNECTED。

- 连接 TIA 后可触发真实部署接口。

- 所有 diagnostics 都能展示。

- 变量表、绑定表、部署计划都能展示。
