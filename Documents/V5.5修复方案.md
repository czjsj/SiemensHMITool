# Claude Code 任务单：修复 HMI 变量类型错误与模板事件变量未替换问题

## 背景

当前自然语言驱动 HMI 画面生成后端已经可以导入变量，但存在两个严重问题：

1. 所有导入的变量都变成 `Int` 类型，这是错误的。  
   例如：
   
   - 按钮变量应为 `Bool`
   
   - 指示灯/状态灯变量应为 `Bool`
   
   - 开关变量应为 `Bool`
   
   - IOField 才根据语义或显式配置推断为 `Int` / `Real` / `String`

2. 生成画面中的事件仍然使用模板变量。  
   例如按钮控件已经克隆并生成了新变量 `BTN_START`，但按钮的 Click/Press/Release 事件里的 FunctionList 仍然引用模板里的旧变量，例如 `Template_Button_Tag`。

目标：修复变量类型推断与模板事件变量重写，确保导入到 TIA Portal 的 HMI Tag 类型正确，并且所有控件事件都绑定到当前生成变量，而不是模板变量。

---

## 总体原则

不要只在 Openness 导入阶段补救。  
正确修复位置应在 XML 生成前：

1. `VariableEngine` 必须生成正确的 `TagSpec.data_type`。

2. `HmiTagXmlBuilder` / `TagXmlBuilder` 必须尊重 `TagSpec.data_type`，不能统一默认成 `Int`。

3. 模板 XML 重写阶段必须重写所有变量引用，包括：
   
   - 控件静态属性里的变量引用
   
   - 动态绑定里的变量引用
   
   - 事件 FunctionList 里的变量引用
   
   - Function 参数里的 `Tag` / `TagName` / `ProcessTag` / `VariableName`

4. 生成完成后必须加模板变量泄漏检查：最终 XML 中不得残留任何模板变量名。

## Step 2：修复 VariableEngine 的语义类型推断

在 `backend/variable_engine.py` 中增加或修正统一的数据类型推断函数。

目标逻辑：

```python
def infer_tag_data_type_for_item(item: dict, role: str | None = None) -> str:
    item_type = normalize_item_type(item.get("type"))

    # 按钮、开关、位操作目标必须是 Bool
    if item_type in {"button", "switch"}:
        return "Bool"

    # 指示灯、状态灯、报警灯默认 Bool
    if item_type in {"indicator", "lamp", "circle", "status_indicator"}:
        explicit = item.get("data_type") or item.get("datatype")
        if explicit:
            normalized = normalize_data_type(explicit)
            # 指示灯如果显式给了 Bool 就保留；如果没有明确数值语义，仍优先 Bool
            return normalized
        return "Bool"

    # SymbolicIO 一般使用 Int 作为文本列表索引
    if item_type in {"symbolic_io", "symbolic_io_field"}:
        return "Int"

    # IOField 根据显式类型或文本语义推断
    if item_type in {"io_field", "input_output_field"}:
        explicit = item.get("data_type") or item.get("datatype")
        if explicit:
            return normalize_data_type(explicit)

        text = str(item.get("text") or item.get("name") or "")
        if any(k in text for k in ["温度", "压力", "速度", "流量", "液位", "设定", "频率", "电流", "电压"]):
            return "Real"

        return "Int"

    # 默认兜底
    explicit = item.get("data_type") or item.get("datatype")
    return normalize_data_type(explicit) if explicit else "Int"
```

同时增加类型归一化函数：

```python
def normalize_data_type(value: str | None, fallback: str = "Int") -> str:
    if not value:
        return fallback

    key = str(value).strip().lower()

    mapping = {
        "bool": "Bool",
        "boolean": "Bool",
        "bit": "Bool",

        "int": "Int",
        "integer": "Int",
        "short": "Int",

        "dint": "DInt",
        "doubleint": "DInt",

        "real": "Real",
        "float": "Real",
        "double": "Real",

        "string": "String",
        "str": "String",
        "char": "Char",

        "word": "Word",
        "dword": "DWord"
    }

    return mapping.get(key, fallback)
```

要求：

- 按钮变量不能再 fallback 成 `Int`

- 指示灯变量不能再 fallback 成 `Int`

- 位操作动作 `SET_BIT` / `RESET_BIT` / `TOGGLE_BIT` 的目标变量必须是 `Bool`

- 如果同一个变量名被多个控件引用，且类型冲突，必须报错，不允许静默覆盖

## Step 3：修复 TagXmlBuilder / HmiTagXmlBuilder 中的默认 Int 覆盖

检查：

- `backend/backends/classic/tag_xml_builder.py`

- `HmiTagXmlBuilder`

- `TagXmlBuilder`

查找类似逻辑：

```python
data_type = "Int"
```

或：

```python
tag_type = tag.get("type", "Int")
```

或：

```python
datatype = normalize(..., fallback="Int")
```

修改原则：

1. XML 生成器不能重新推断业务语义。

2. XML 生成器只能使用 `TagSpec.data_type`。

3. 只有在完全没有类型时，才允许 fallback。

4. fallback 前应输出 warning，方便定位上游缺失类型。

建议实现：

```python
def get_tag_data_type(tag) -> str:
    raw = (
        getattr(tag, "data_type", None)
        or getattr(tag, "datatype", None)
        or getattr(tag, "type", None)
    )

    if not raw:
        logger.warning("Tag %s has no data_type, fallback to Int", getattr(tag, "name", "<unknown>"))
        return "Int"

    return normalize_data_type(raw)
```

验收：

- 输入 `TagSpec(name="BTN_START", data_type="Bool")`

- 输出 HMI Tag XML 中必须是 `Bool`

- 不允许输出为 `Int`

## Step 4：修复按钮事件生成逻辑

检查以下文件：

- `backend/backends/classic/function_list_builder.py`

- `backend/backends/classic/screen_xml_builder.py`

- `backend/template_xml_generator.py`

- `backend/template/xml_rewrite_rules.py`

- `backend/template/event_pattern_extractor.py`

- `backend/template/prototype_registry.py`

- `backend/backends/classic/classic_screen_reference_rewriter.py`

目标：

按钮事件不能继续沿用模板变量。  
模板只能提供事件结构，事件目标变量必须来自当前 IR / 当前控件绑定。

规则：

1. Momentary 按钮：
   
   - Press 事件：`SetBit(BTN_xxx)`
   
   - Release 事件：`ResetBit(BTN_xxx)`

2. Toggle 按钮：
   
   - Click 事件：`ToggleBit(BTN_xxx)`

3. Set 按钮：
   
   - Click 事件：`SetBit(BTN_xxx)`

4. Reset 按钮：
   
   - Click 事件：`ResetBit(BTN_xxx)`

示例伪代码：

```python
def build_button_events_for_item(item):
    tag_name = resolve_primary_tag_name(item)
    behavior = resolve_button_behavior(item)

    if behavior == "momentary":
        return [
            EventSpec(trigger="PRESS", actions=[ActionSpec(type="SET_BIT", target=tag_name)]),
            EventSpec(trigger="RELEASE", actions=[ActionSpec(type="RESET_BIT", target=tag_name)]),
        ]

    if behavior == "toggle":
        return [
            EventSpec(trigger="CLICK", actions=[ActionSpec(type="TOGGLE_BIT", target=tag_name)])
        ]

    if behavior == "reset":
        return [
            EventSpec(trigger="CLICK", actions=[ActionSpec(type="RESET_BIT", target=tag_name)])
        ]

    return [
        EventSpec(trigger="CLICK", actions=[ActionSpec(type="SET_BIT", target=tag_name)])
    ]
```

优先方案：

- 对按钮事件使用 `FunctionListBuilder` 重新生成，而不是完整复制模板事件。

- 如果必须复制模板事件，则复制后必须重写 FunctionList 内所有变量引用。

## Step 5：修复模板 XML 变量引用重写范围

在 `ClassicScreenReferenceRewriter` 或模板 V4 重写流程中新增统一方法：

```python
def rewrite_all_tag_references(xml_node, tag_rewrite_map: dict[str, str]) -> None:
    for elem in xml_node.iter():
        # 1. 重写元素文本
        if elem.text:
            old = elem.text.strip()
            if old in tag_rewrite_map:
                elem.text = tag_rewrite_map[old]

        # 2. 重写 tail 中可能出现的变量
        if elem.tail:
            old_tail = elem.tail.strip()
            if old_tail in tag_rewrite_map:
                elem.tail = tag_rewrite_map[old_tail]

        # 3. 重写属性值
        for attr_name, attr_value in list(elem.attrib.items()):
            if attr_value in tag_rewrite_map:
                elem.attrib[attr_name] = tag_rewrite_map[attr_value]

        # 4. 处理 Name="TagName" / Name="ProcessTag" 这种参数结构
        param_name = elem.attrib.get("Name") or elem.attrib.get("name")
        if param_name in {
            "Tag",
            "TagName",
            "ProcessTag",
            "Variable",
            "VariableName",
            "ConnectionTag",
            "ValueTag"
        }:
            if elem.text and elem.text.strip() in tag_rewrite_map:
                elem.text = tag_rewrite_map[elem.text.strip()]
```

需要覆盖的 XML 位置：

- `TagName`

- `ProcessTag`

- `Variable`

- `VariableName`

- `ConnectionTag`

- `ValueTag`

- `FunctionList`

- `Function`

- `Parameter`

- `Arguments`

- 动态属性绑定节点

- 事件节点

注意：

- 不要只重写控件根节点属性。

- 必须对整个克隆后的控件 XML 子树做递归扫描。

- 重写必须发生在控件克隆之后、最终 XML 写盘之前。

## Step 6：构建 template_tag -> actual_tag 映射

在模板原型匹配或 XML 重写阶段，为每个克隆控件建立变量映射。

示例：

```python
tag_rewrite_map = {
    template_primary_tag: actual_primary_tag,
    template_event_tag: actual_primary_tag,
    template_dynamic_tag: actual_primary_tag,
}
```

变量来源优先级：

1. 当前 item 的 `tag_binding`

2. 当前 item 的 `process_tag`

3. 当前 item 的 `bindings[0].tag`

4. 当前 item 的事件 action target

5. `VariableEngine` 生成的 primary tag

对于按钮控件：

- 模板按钮原来的事件变量统一映射到当前按钮的 Bool 变量

对于指示灯：

- 模板指示灯原来的动态绑定变量统一映射到当前指示灯的 Bool 变量

对于 IOField：

- 模板 IOField 原来的过程变量统一映射到当前 IOField 变量

- `ClassicScreenReferenceRewriter`

- 或 `template_binding_validator.py`

- 或 `template_xml_generator.py` 生成结束前

实现：

```python
def assert_no_template_tag_leak(xml_root, template_tag_names: set[str]) -> None:
    xml_text = ET.tostring(xml_root, encoding="unicode")

    leaked = sorted([
        name for name in template_tag_names
        if name and name in xml_text
    ])

    if leaked:
        raise ValueError(
            "Template tag leaked into generated screen XML: "
            + ", ".join(leaked)
        )
```

## Step 8：增加语义校验，防止错误变量类型进入导入阶段

在 IR V2 验证或部署前验证中增加检查：

```python
BIT_ACTIONS = {"SET_BIT", "RESET_BIT", "TOGGLE_BIT"}

def validate_action_target_types(spec):
    tag_by_name = {tag.name: tag for tag in spec.tags}

    for screen in spec.screens:
        for item in screen.items:
            for event in getattr(item, "events", []) or []:
                for action in getattr(event, "actions", []) or []:
                    action_type = str(action.type).upper()
                    if action_type in BIT_ACTIONS:
                        target = action.target
                        tag = tag_by_name.get(target)
                        if not tag:
                            raise ValueError(f"Action target tag not found: {target}")

                        if normalize_data_type(tag.data_type) != "Bool":
                            raise ValueError(
                                f"Bit action {action_type} target {target} must be Bool, got {tag.data_type}"
                            )
```

放置位置可以是：

- `backend/domain/validation.py`

- `backend/validation/tag_binding_gate.py`

- `backend/services/verification_service.py`

建议：  
生成前轻量校验放在 `domain/validation.py`，部署前阻断校验放在 `tag_binding_gate.py`。
