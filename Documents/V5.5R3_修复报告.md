# V5.5 R3 修复报告 — VariableEngine 数据回写断裂修复

**日期**: 2026-06-21  
**状态**: ✅ 636 测试全部通过（含 2 个新增回归测试）

---

## 问题复述

V5.5 R2 修复后，用户在实际 TIA Portal 流程中错误依然存在：
- 所有导入的 HMI 变量仍被标记为 `Int`（按钮/指示灯应为 `Bool`）
- 模板复制的控件中仍残留模板变量名

## 根因分析：VariableEngine.generate() 数据回写断裂

经过逐行追踪完整流水线，定位到两个交叠的根因：

### 根因 1（主因）：generate() 的修正结果不回写到 legacy IR

**完整追踪链路**：

```
AI 生成 IR: tags=[{"name":"BTN_Start","data_type":"Int"}]
    ↓
generate(ir):
    existing_tags = {"BTN_Start": {"data_type": "Int"}}  ← 来自原始 IR
    ↓
    enrich(ir):
        adapter.convert: TagSpec("BTN_Start", data_type="Int")  ← 保留 AI 的 Int
        _enrich_button: existing.data_type = "Bool"  ← R2 修正，但只改了 project.tags
    ↓
    回填循环: tag.name="BTN_Start" in existing_tags → SKIP  ← 已有 tag，不写入 new_tags
    ↓
    合并: ir["tags"] 仍是 AI 原始的 Int  ← 修正丢失！
    ↓
sync_tags(ir["tags"]) → TIA Portal 收到 Int
```

**问题代码**（`variable_engine.py` 第 334-343 行）：
```python
for tag in project.tags:
    if tag.name not in existing_tags:  # ← 已有 tag 被跳过
        new_tags_for_legacy.append({...})
```

`enrich()` 阶段在 `project.tags` 中正确修正了 data_type（Bool/Real），但 `generate()` 的回填循环只添加新 tag，从不更新已有 tag 的 data_type。最终 `sync_tags()` 使用的 `ir["tags"]` 数组仍保留 AI 输出的错误类型。

### 根因 2（次因）：_enrich_iofield 缺少已有 tag 类型修正

`_enrich_button` 和 `_enrich_indicator` 在 R2 中已加入修正逻辑，但 `_enrich_iofield` 漏掉了：
```python
if existing_tag:
    if existing_tag not in existing_tags:
        ...  # 创建新 tag
    return  # ← 已有 tag 时直接返回，不修正类型
```

### 根因 3（次因）：AI prompt 未强制要求数据类型映射

`prompts.py` 中 `TAG_CONVENTIONS` 缺少对 `data_type` 的显式规则。AI 可能将所有变量输出为 `Int`。

## 修复内容

### 1. `backend/variable_engine.py` — generate() 增加 data_type 回写同步

在合并 tags 之前，将 `project.tags` 中修正后的 data_type 同步回 `ir["tags"]`：

```python
# V5.5R3: 将 enrich 阶段修正后的 data_type 同步回 legacy IR
_project_tag_types: Dict[str, str] = {}
for t in project.tags:
    if t.name and t.data_type:
        _project_tag_types[t.name] = t.data_type
for legacy_tag in ir.get("tags", []):
    name = (legacy_tag.get("name") or "").strip()
    corrected = _project_tag_types.get(name)
    if corrected and legacy_tag.get("data_type") != corrected:
        legacy_tag["data_type"] = corrected
```

### 2. `backend/variable_engine.py` — _enrich_iofield 已有 tag 类型修正

为 `_enrich_iofield` 补全与 `_enrich_button`/`_enrich_indicator` 同等的已有 tag 类型修正逻辑，使用 `infer_tag_data_type_for_item()` 推断正确类型。

### 3. `backend/prompts.py` — TAG_CONVENTIONS 增加 data_type 硬性规则

```
4. 变量数据类型（data_type）硬性规则 — 绝对不允许将所有变量都设为 Int：
   - 按钮关联的变量 → 必须设为 "Bool"
   - 指示灯关联的变量 → 必须设为 "Bool"
   - 报警/故障标志变量 → 必须设为 "Bool"
   - 数值 IO 域变量（含物理量关键词）→ 必须设为 "Real"
   - 符号 IO 域变量 → 可设为 "Int"
   - 严禁不加区分地将所有变量设为 Int
```

### 4. `tests/test_v55_integration_regression.py` — 2 个新增回归测试

- `test_ai_generated_int_types_corrected_to_bool` — 模拟 AI 输出 Int，验证按钮/指示灯被纠正为 Bool
- `test_ai_generated_int_type_not_synced_to_legacy_tags` — 直接检查 `ir["tags"]` 数组，确保所有已有 tag 的 data_type 被正确覆盖
