## 1. 项目概述

Siemens HMI Assistant 是一个 AI 驱动的 TIA Portal HMI 画面自动生成与部署工具。用户通过自然语言（中文）描述 HMI 画面需求，系统经 LLM 转换为结构化 IR（中间表示），再生成符合西门子 TIA Portal 规范的 XML，最终通过 Openness API 导入到正在运行的博途工程中。

**核心能力**：
- 自然语言 → HMI 画面 IR（JSON）
- IR → SimaticML XML / 模板改写 XML
- 变量自动生成（命名、类型推断、绑定）
- Openness API 连接 TIA Portal 并执行导入/创建/编译
- MiMo 视觉审查 → 自动迭代修正

**运行环境**：Windows + TIA Portal + Openness PublicAPI + pythonnet

## 4. 核心模块详解

### 4.1 入口层（Layer 0）

Flask 路由层（在 `app.py` 中，非 backend 模块）提供 SSE 事件流和 REST API，调用 `pipeline_orchestrator` 和 `deployment_service`。

### 4.2 编排层（Layer 1）

#### pipeline_orchestrator.py（595 行）
**多阶段流水线状态机**：

```
pipeline_start → [image_analysis] → generate_start →
review_start → review_result →
  ├─ review_pass → pipeline_done
  ├─ 达到最大迭代 → pipeline_done
  └─ regenerate_start → (回到 generate_start)
```

- 集成 LLM、MiMo 视觉审查、IR 校验
- 所有阶段通过 `yield (event_name, data)` 返回 SSE 事件
- 支持自动分辨率适配（`scale_ir_to_resolution`）

#### deployment_service.py（945 行）
**统一部署流水线状态机**：

```
DRY_RUN → NOT_CONNECTED → BLOCKED → DEPLOYING → DEPLOYED
                                              ↘ FAILED
                                              ↘ VERIFICATION_FAILED
                                              ↘ COMPILE_FAILED
```

- 绑定 Legacy IR → VariableEngine.enrich → validate → BackendFactory → execute → verify → compile
- 禁止 V3 部署入口回退到旧 `generate_simaticml()`

### 4.3 语义层（Layer 3）

#### hmi_ir.py（528 行）
**IR 校验与归一化**：
- JSON 结构检查、必填字段断言
- 交叉引用校验（tag 引用一致性）
- 布局自动优化（重叠检测、行间距、过密调整）
- 支持 Basic / Comfort / Unified 三种 HMI 类型
- 分辨率支持：1920×1080, 1280×800, 1024×768, 800×480, 480×272 等

#### variable_engine.py（1329 行）
**变量引擎核心**：
- 变量前缀规则：`BTN_`（瞬时按钮）、`MEM_`（切换按钮）、`STS_`（状态指示灯）、`LMP_`（报警灯）、`IO_`（IO 域）、`SIO_`（符号 IO 域）
- Button 行为检测：momentary / toggle
- Indicator 颜色与闪烁变量绑定
- IOField 数据类型推断
- V3.0 改造：核心逻辑输出语义模型 `HmiProjectSpec`，VBS 生成仅保留 backward-compat 层

#### tag_binding_normalizer.py（579 行）
**变量绑定规范化**：
- 统一 legacy IR 中的 `process_tag` / `tag_binding` / `binding.tag` 字段
- 根据对象类型和名称自动生成变量名
- TIA 变量名非法字符过滤

#### domain/ir_v2.py
**Pydantic V2 数据模型**（方案文档 §6 对齐）：
- `TagSpec`, `ScreenItemSpec`, `ScreenSpec`, `HmiProjectSpec`, `TargetSpec`
- `DeploymentPolicies`, `ProjectMetadata`
- `ActionSpec`, `BindingSpec`, `EventSpec`, `GeometrySpec`
- 不依赖 Flask、pythonnet 或 Siemens DLL

### 4.4 XML 生成层（Layer 4）

#### simaticml_generator.py（701 行）
**SimaticML XML 生成**：
- SimaticML 命名空间：`http://www.siemens.com/automation/SimaticML`
- 支持对象：IOField, SymbolicIOField, Button, Circle/Indicator, TextField
- MultilingualText 严格格式：`<MultilingualText><Text Language="zh-CN">...</Text></MultilingualText>`
- 颜色 ARGB 转换、字体大小、动态化属性
- 版本兼容说明（TIA V16/V17/V18/V19）

#### template_xml_generator.py（1264 行）
**模板 XML 改写**：
- 以 TIA Portal 手工导出的模板 XML 为基底
- 根据 IR 安全替换字段，保持原始结构/命名空间/ID 不变
- 匹配策略：template_ref → id → 名称前缀
- 类型映射：IOField, Button, SymbolicIOField, Circle→Indicator, TextField→Text

#### backends/classic/tag_xml_builder.py（542 行）
**Tag XML 构建器**：
- `TagXmlBuilder`：生成 `<SW.Tag>` PLC Tag XML（`<Document>` 根 + SimaticML 命名空间）
- `HmiTagXmlBuilder`：生成 HMI Tag XML（`<Engineering>` 根 + HmiTagML 命名空间）
- **关键约束**：`SW.Tag` 是 `Siemens.Engineering.SW.Tag`（PLC Software Tag 类型），会被 `Hmi.Tag.TagComposition.Import` 拒绝
- V5.5R8+：HMI Tag XML 中不再包含 `DataType`（导入后通过 API 修正）

### 4.5 导入层（Layer 5）

#### xml_validator.py（864 行）
**XML 预导入校验闸门**：
- 管道第四层，ImportEngine 的上游
- HTML 标签检测（禁止 `<div>`, `<span>` 等，允许 TIA Rich Text 的 `<body>` + `<p>`）
- MultilingualText 结构校验（支持 V16/Comfort 和通用格式）
- 禁止 `<MultilingualText><ID>...</ID>...</MultilingualText>` 结构
- `_has_any_sw_indicator()`：检测 SW.Tag / SW.Blocks，对 HMI 导入目标报 TAG_XML_WRONG_CLASS
- `validate_xml_class_for_import_target()`：类级导入目标验证
- 不通过 → 直接阻断，不尝试部分修复

#### import_engine.py（408 行）
**TIA 导入引擎（终端层）**：
- 分层：预处理 → 校验闸门 → 导入
- 强制约束：Fail Fast, No Partial Fix, No Hacks
- 唯一允许的导入方式：`Screens.Import(FileInfo, ImportOptions.Override)`
- 禁止：ScreenComposition.Import、反射 Import、temp ASCII hack

#### openness_manager.py（2872 行）
**Openness Façade**（第二大文件）：
- V3.0 内部委托：SessionManager, DeviceDiscovery, HmiCompiler, ExceptionMapper, AssemblyLoader
- 向后兼容旧 API，旧调用方式不破坏
- `sync_tags()` 路由策略：
  - 主路径：`create_hmi_tags_via_api`（单参 `Create(name)` + Reflection `Enum.Parse` 设置 DataType）
  - 回退：`import_hmi_tags_safe`（XML Import → `_correct_tag_data_types_after_import`）
- 诊断模式：非 Windows / 无 pythonnet 时自动降级

#### openness/classic_executor.py（3651 行）
**Classic HMI Openness 执行器**（最大文件）：
- 真实 TIA Portal API 调用封装
- 执行顺序：connections → tags → text_lists → scripts/resources → screens → compile → verify
- `import_hmi_tags_safe()`：XML Import 主路径（ImportOptions 解析 → 临时文件写入 → Tags.Import）
- `create_hmi_tags_via_api()`：Create API 主路径（V5.5R10 单参 `Create(name)` + `Enum.Parse` + `PropertyInfo.SetValue`）
- `_upsert_tags_to_default_table()`：逐标签创建/更新（已存在匹配跳过，类型不匹配更新）
- `_correct_tag_data_types_after_import()`：导入后类型修正（Reflection + Enum.Parse）
- `resolve_import_option()`：检测可用 ImportOptions（Overload → Direct → Standard）

#### openness/unified_executor.py（595 行）
**Unified HMI Openness 执行器**：
- `hmiSoftware.Tags`（直接集合，非 TagFolder.Tags）
- `hmiSoftware.Screens`（直接集合）
- ScreenItems → 属性 setter → Dynamizations.Create → EventHandlers.Create → ScriptCode setter
- RuntimeContract 机制：缺失则自动 probe

## 5. 关键数据流

### 5.1 变量同步流程（V5.5R10）

```
VariableEngine.enrich(ir)
  → tag_items = [{"name": "BTN_Start", "data_type": "Bool", ...}, ...]
  → OpennessManager.sync_tags(sw, tag_items)
      ├─ 主路径：create_hmi_tags_via_api(sw, tag_items)
      │   ├─ tags_collection = hmi.TagFolder.DefaultTagTable.Tags
      │   ├─ tag = tags_collection.Create(name)           # 单参数
      │   └─ PropertyInfo.SetValue(tag, Enum.Parse(enumType, data_type))
      │                                        # Reflection + Enum.Parse
      └─ 回退路径：import_hmi_tags_safe(sw, tags_xml, tag_items)
          ├─ HmiTagXmlBuilder.build_batch_tags_xml(tag_items)
          │   └─ Engineering + HmiTagML 格式（无 DataType）
          ├─ tags.Import(fileInfo, importOptions)
          └─ _correct_tag_data_types_after_import()
              └─ PropertyInfo.SetValue + Enum.Parse（同主路径）
```

### 5.2 画面生成流程

```
LLM 生成 JSON IR
  → hmi_ir.validate_ir(ir)         # 结构校验 + 布局优化
  → VariableEngine.enrich(ir)      # 变量生成 + 绑定
  → tag_binding_normalizer         # 绑定规范化
  → validation.tag_binding_gate    # 绑定闸门
  → BackendFactory.get(tagetspec)  # 选择后端
  → backend.build_plan(spec)       # 构建部署计划
  → backend.execute(plan)          # 执行部署
  → backend.verify(spec)           # 验证
  → compiler.compile()             # 编译
```

## 7. .NET Interop 层

### 7.1 pythonnet 桥接

- 通过 `clr.AddReference()` 加载 `Siemens.Engineering.dll`
- .NET 对象直接映射为 Python 对象
- **关键限制**：pythonnet 无法自动将 Python `str` 转换为 .NET enum 类型

### 7.2 DataType 设置策略（V5.5R10）

TIA Portal 中 HMI Tag 的 `DataType` 属性是 .NET enum 类型（如 `HmiDataType`），不是 string 属性。

**三层回退策略**：
```python
# 第一层：System.Reflection + Enum.Parse（主策略）
from System import Enum
tag_type = tag.GetType()
dt_prop = tag_type.GetProperty("DataType")
if dt_prop.PropertyType.IsEnum:
    dt_prop.SetValue(tag, Enum.Parse(dt_prop.PropertyType, "Bool"))

# 第二层：直接赋值 fallback
tag.DataType = "Bool"

# 第三层：读回验证
actual = tag.DataType  # 验证是否持久化
```

### 7.3 TagComposition.Create 约束

- `TagComposition.Create` 只有单参重载：`Create(string name)`
- 传第二个参数会被 pythonnet 静默丢弃，不抛异常
- 因此 DataType 必须在创建后单独设置

## 8. 已知技术问题

### 8.1 HMI Tag DataType 导入问题（V5.5R10 待验证）

**现象**：HMI Tag XML 导入成功后所有变量类型默认 Int
**根因链**：
1. XML Import 不接受 DataType（任何形式）
2. `Create(name, data_type)` 二参数被静默丢弃
3. `tag.DataType = "Bool"` 因属性为 .NET enum 而静默失败
**修复**：`Create(name)` + `Enum.Parse` + `PropertyInfo.SetValue`
**状态**：代码已修改，637 tests pass，待 TIA Portal 真实验证

### 8.2 XML 格式矛盾

| 来源 | 根元素 | 标签类型 | 命名空间 |

## 10. 架构评价

### 优点
1. **管道化设计清晰**：生成 → 校验 → 导入 层层递进，每层职责单一
2. **防御性编程**：XML 验证闸门、多层 fallback、读回验证
3. **抽象分离好**：`domain/ir_v2` 纯数据模型不依赖任何外部库
4. **向后兼容**：OpennessManager 保留旧 API，V3 模块化分解不破坏现有调用
5. **两种 XML 路径并存**：SimaticML 生成（从零构建）和模板改写（保留真实结构），适应不同场景

### 待改进
1. **`classic_executor.py` 过大**（3651 行）：包含 Tag、Screen、Connection、TextList、Script 等所有操作，建议按功能域拆分
2. **`openness_manager.py` 过大**（2872 行）：Façade 层混入了过多业务逻辑（sync_tags 含变量同步路由决策）
3. **XML 格式碎片化**：`golden_hmi_tag_template.xml`、`HmiTagXmlBuilder`、`TagXmlBuilder` 三套格式并存，真实可用格式尚未最终验证
4. **测试覆盖不足**：核心 TIA API 交互依赖 mock，无 TIA Portal 集成测试
