# Siemens HMI Assistant — 前端功能总览

## 一、技术栈

| 项    | 说明                             |
| ---- | ------------------------------ |
| 框架   | 原生 HTML + JavaScript（无三方框架）    |
| 样式   | 原生 CSS，深色青绿主题，支持明暗切换           |
| 通信   | REST API + SSE 流式              |
| 模板引擎 | Jinja2（`templates/index.html`） |

## 三、模块功能详解

### 3.1 顶栏 (Top Bar)

- **品牌区**：显示 "Siemens HMI Tool" 标题及青绿色 Logo
- **余额显示**：显示 API 余额信息（`#balancePill`）
- **博途连接区**：
  - 连接状态指示灯（绿=已连接，红=未连接）
  - 连接 / 断开 / 校准 / 诊断 四个操作按钮
  - 连接后显示项目名称
- **主题切换**：明暗主题一键切换
- **设置入口**：打开模型与接口设置模态框

### 3.2 左侧面板 — 画面需求输入

- **模型选择下拉框**：列出所有可用的 LLM 服务商及配置状态
- **需求文本域**：输入自然语言描述 HMI 画面需求，支持中文
- **文件上传区（拖拽/点击）**：
  - 支持图片（`image/*`）、PDF、TXT、MD、CSV
  - 拖拽或点击选择，显示文件标签（chip），可逐个删除
- **选项行**：
  - **思考深度**：关闭 / 低 / 中 / 高
  - **展示思考过程**：是否显示模型推理过程
  - **流式输出**：是否启用 SSE 流式
  - **视觉审查 (MiMo)**：是否启用多阶段视觉审查流水线
- **示例快捷填充**：电机控制、登录界面、温度监控、流量动画 四个预设示例
- **生成按钮**：主要操作入口，点击后切换为停止按钮

### 3.3 右侧面板 — 三标签页

#### 标签页 1：AI 输出

- **思考过程区**（可折叠）：显示模型推理内容，生成中显示旋转动画
- **流水线进度区**（审查模式专用）：
  - 步骤指示器：生成初始画面 → MiMo 视觉审查 → 修正画面
  - 实时更新审查进度、评分、通过/失败状态
  - 显示审查结果的详细分类：布局对齐、组件尺寸、颜色规范、文字可读性、元素完整性、专业质量
  - 显示关键问题和改进建议
- **输出工具条**：
  - 生成 XML / 预览按钮
  - 复制输出内容按钮
  - 下载 .xml 按钮
- **输出内容区**：显示模型原始输出（画面 IR / JSON）

#### 标签页 2：画面预览

- **预览元信息**：标题、画面名、分辨率、HMI 类型、对象数量
- **缩放选择**：40%/50%/65%/80%/100%
- **SVG 画布**：基于 IR 数据动态渲染的画面预览，包含：
  - 背景矩形
  - 静态文本（Text）
  - 文本 IO 域（IOField，蓝色边框）
  - 符号 IO 域（SymbolicIOField，紫色边框，下拉三角）
  - 按钮（Button，绿色圆角矩形，脚本标记点）
  - 圆形指示灯（Indicator，闪烁动画支持）
- **图例**：各类型颜色标识

#### 标签页 3：配置

- **编辑模式切换**：表单编辑 / 原始 YAML
- **表单编辑模式**包含的配置项：
  - **Openness 连接**：TIA 版本、DLL 路径、HMI 设备名、附加实例、编译/保存选项、生成模式
  - **经典模板 XML 设置**：启用开关、模板画面名、模板路径、导出/生成目录
  - **HMI 默认模板设置**：Basic / Comfort / Unified 三合一卡片式配置
  - **Unified 直接绘制设置**：启用、更新已有画面、清空已有对象、不支持对象策略
  - **HMI 默认参数**：分辨率、HMI 类型、背景色
  - **输出设置**：导出目录、编码格式
  - 保存 / 重新加载按钮
- **原始 YAML 模式**：直接编辑 `config.yaml` 全文

### 3.4 底部操作区

#### 导入栏

- **生成模式选择**：自动判断 / Unified 直接绘制 / 经典模板 XML / 原 SimaticML 导入
- **导入选项**：导入后编译、完成后保存项目、UTF-8 含 BOM
- **导出模板按钮**：打开导出模板对话框，指定画面名称和导出目录
- **导入到博途按钮**：将生成的画面导入 TIA Portal

#### HMI 能力信息条（连接后显示）

- 设备名、HMI 类型（Basic/Comfort/Unified）
- 推荐生成模式
- 可用画面列表
- 警告信息

#### 导入日志

- 可折叠的时间戳日志，支持 ok / err / warn 三种颜色标识

### 3.5 模态框

#### 模型与接口设置

- 当前服务商选择、Base URL、API Key
- 对话模型 (chat) 和推理模型 (reasoner) 设置
- 视觉支持开关
- **MiMo 视觉审查专设**：
  - 启用开关、Base URL、API Key、模型名
  - 最大迭代次数、审查通过阈值
- 测试连接按钮、保存按钮

#### Openness 环境诊断

- 操作系统检测
- pythonnet 安装状态
- Openness DLL 存在性
- 博途进程检测
- Openness 用户组提示
- 重新诊断按钮

#### 导出模板画面

- 模板画面名称输入
- 导出目录输入
- 导出 / 取消按钮

### 3.6 Toast 通知

- 底部居中的临时消息提示
- 支持成功（青色）和错误（红色边框）两种样式
- 自动在 2.6 秒后消失

## 四、JavaScript 核心逻辑（app.js）

### 4.1 初始化流程

1. `DOMContentLoaded` → `init()`
2. 绑定所有 UI 事件 (`bindUI()`)
3. 加载配置 (`loadConfig()`)：`GET /api/config`
4. 根据配置填充所有下拉框、复选框、表单

### 4.2 流式生成（SSE）

- 端点：`/api/generate`（普通模式）或 `/api/generate/with_review`（审查模式）
- 支持文件上传时使用 `multipart/form-data`
- 通过 `AbortController` 支持中途停止
- SSE 事件流处理：
  - `start` — 生成开始，含思考深度信息
  - `thinking` — 思考过程增量
  - `content` — 模型输出内容增量
  - `parsed_ok` / `parse_warn` — 解析结果
  - `error` — 错误信息
  - `done` — 生成完成

### 4.3 MiMo 视觉审查流水线

- 通过 SSE 事件驱动多阶段审查进度：
  - `pipeline_start` — 初始化流水线 UI
  - `image_analysis_start/result` — 参考图片分析
  - `generate_start` — AI 生成阶段
  - `review_start/progress/result` — 视觉审查阶段
  - `review_pass` — 审查通过
  - `regenerate_start` — 根据审查意见修正
  - `pipeline_done` — 流水线完成
- 实时更新步骤指示器、审查结果分类、评分

### 4.4 IR → XML 构建与预览

- `POST /api/build` — 将 IR JSON 转换为 SimaticML
- 审查模式自动静默构建预览 (`autoBuildPreview()`)
- SVG 预览渲染 (`renderPreview()`)：
  - 根据 IR 的 `_screen_size` 创建等比例 SVG 画布
  - 支持 5 种 HMI 元素类型：Text、IOField、SymbolicIOField、Button、Indicator
  - Indicator 支持闪烁动画（SVG `<animate>`）
  - 按钮支持脚本标记显示

### 4.5 博途 Openness 集成

- **连接** (`POST /api/openness/connect`)：连接已打开的 TIA Portal 项目
- **断开** (`POST /api/openness/disconnect`)：断开连接
- **校准** (`POST /api/openness/export-reference`)：导出参考画面用于格式匹配
- **导入** (`POST /api/openness/import`)：支持 IR+模式 或 XML路径 两种方式
- **导出模板** (`POST /api/openness/export-template`)：导出模板画面 XML
- **能力查询** (`GET /api/openness/capabilities`)：获取 HMI 设备能力信息
- **诊断** (`GET /api/openness/diagnose`)：环境诊断

### 4.6 配置管理

- **表单保存**：将表单值映射回 CONFIG 对象，`POST /api/config`
- **原始 YAML 保存**：`POST /api/config/raw`
- **设置保存**：保存 LLM 服务商配置 + MiMo 配置
- **HMI 类型归一化** (`normalizeHmiType()`)：将各种 HMI 类型名称统一为 basic / comfort / unified
- **默认模板自动匹配** (`applyDefaultTemplateForType()`)：根据 HMI 类型应用对应的默认模板配置

### 4.7 其他功能

- **示例填充** (`fillExample()`)：4 个预定义示例描述
- **文件管理**：添加/删除上传文件，Chip 标签展示
- **日志系统**：带时间戳、颜色分类的日志输出
- **主题切换**：`body.light` 类切换明暗主题

## 五、数据流与状态管理

```
config.yaml (后端)
      ↓ GET /api/config
   CONFIG (全局 JS 对象)
      ↓ 用户操作
   表单/选项变更 → CONFIG 属性更新
      ↓ POST /api/config
 config.yaml (后端持久化)
```

```
用户需求文本 → POST /api/generate → SSE 流 → outputBody 回显 + thinking 回显
                                                       ↓
                                              POST /api/build
                                                       ↓
                                              LAST_BUILD (XML + IR)
                                                  ↓          ↓
                                        renderPreview()   downloadXml()
```

```
博途连接 → GET /api/openness/capabilities → LAST_CAPS
                                                 ↓
                                    HMI 能力信息条回显 + 默认模板自动匹配
```

## 六、CSS 设计要点

- **设计系统**：CSS 变量驱动的深色青绿主题（`--accent: #16e0b3`）
- **明暗双主题**：通过 `body.light` 切换变量值实现
- **响应式**：grid 布局，配置卡片在窄屏下变为单列
- **交互反馈**：hover 状态、animations（fadeIn / spin）、transition 过渡
- **自定义滚动条**：适配深色主题的细滚动条
- **Flask 静态文件缓存策略**：CSS/JS 引用带 `?v=2` 版本号
